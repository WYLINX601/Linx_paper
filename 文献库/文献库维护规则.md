# 文献库维护规则

本页规定文献库“怎样放、怎样记、什么算读过”。它不判断研究真假，也不替代 Zotero、原论文或主题页的判断。

## 一、四类对象分开

| 类型 | 实际位置 | 主要职责 | 不承担 |
|---|---|---|---|
| **单篇笔记** | `文献库/作者-年份-短题.md` | 一篇来源的阅读范围、原文定位、贡献与参考价值 | 不代替原论文；不把同一来源的多个专题页重复算作多篇 |
| **专题精读** | `文献库/专题精读/<专题>/` | 围绕一个来源或一个问题组织多页阅读、比较与讨论 | 不因页数多就宣称多篇全文精读 |
| **原生导图** | `文献库/文献导图/<组>/*.smm.md` | 阅读组织、比较与提问视图 | 不单独构成文献、证据或研究结论 |
| **索引与记录** | `文献库/README.md`、`文献总索引.md`、`核读记录/`、`文献获取/` | 导航、汇总、复核与获取状态 | 不替代原论文或研究判断 |

同一来源可以同时有单篇笔记、专题精读和导图，这是“一源多视图”，不是三篇独立文献。专题页应链接回单篇笔记或 Zotero 条目，说明新增的是哪一段阅读、比较或讨论。

## 二、单篇笔记的最低字段

新建或大幅修订单篇笔记时，frontmatter 至少保留：

```yaml
title: 原文题名
authors: [作者]
year: 2024
type: paper-reading
paper_id: zotero:ITEMKEY      # 兼容旧字段；新笔记优先 zotero_item
zotero_item: ITEMKEY          # 可选，但推荐
zotero_attachment: PDFKEY     # 有附件时
reading_status: 精读          # 精读／局部精读／初读／摘要初读
read_scope: 印刷页…／PDF页…    # 实际读了哪里，不能只写“已读”
topics: [关键词]
contribution_primary: 框架模型型
reference_value: 核心参考／背景参考／方法参考
updated: 2026-11-04
```

- `title`、`authors`、`year`、`reading_status`、`read_scope` 是最低要求；缺项时在索引中显示 `—`，不补猜。
- `paper_id` 的旧写法 `zotero:KEY` 继续兼容；新增笔记优先写 `zotero_item`。DOI 写入 `doi`，不要和 Zotero key 混用。
- `read_scope` 必须能回到原页：写印刷页、PDF页或章节，不只写“通读”。未读部分要明确写“未读／仅摘要／仅题录”。
- `topics` 是检索关键词，不等于正式研究主题名；主题归属仍在主题页或成果包中维护。

## 三、阅读状态只用四种

| 状态 | 含义 |
|---|---|
| `精读` | 已读目标正文的主体，能定位关键论证与页码；不要求逐页穷尽图表 |
| `局部精读` | 只读指定章节、图表或与当前问题相关的段落 |
| `初读` | 只读摘要、目录、引言或有限页面，尚不足以支撑细节引用 |
| `摘要初读` | 只有题录／摘要／外部介绍，未取得或未读正文 |

“下载成功”“有 PDF”“Zotero 有条目”都不等于已读。旧笔记里的英文状态或复合状态可以保留，但索引会按原值显示，不强行改成四类。

## 四、专题精读与导图的边界

- 专题 `README.md` 至少写明：来源、实际读过的页码／章节、产出的比较或讨论、未读部分、与单篇笔记的关系。
- 导图是阅读视图；导图节点进入正式研究时，应回到单篇笔记、原文页码或成果包主源，不能以导图本身作为引文。
- 同一专题的不同页面可以互相引用，但不要在多个页面各写一份“阅读范围”；阅读范围以单篇笔记或专题 README 为主源。
- 新增导图不自动改变论文篇数、精读篇数或证据数量。

## 五、索引与生成

- `文献库/文献总索引.md`、`文献库/README.md` 的文献目录、`专题精读/README.md`、`文献导图/README.md`、`核读记录/README.md`、`文献获取/README.md` 由 `项目管理/健康检查/literature_views.py` 生成。
- 不手工编辑 README 中 `<!-- literature-catalog:start -->` 与 `<!-- literature-catalog:end -->` 之间的内容；增删笔记后运行生成器并检查差异。
- 生成器只读取 frontmatter 与目录结构，不重新精读、不核验 Zotero 元数据，也不把文件数当作论文数或完成度。
- 检查：`python 项目管理/健康检查/literature_views.py --check`；需要发布时先生成到 Paper 外的临时目录，再用 `mac-paper` 按当前 SHA 写回。

## 六、命名、迁移与归档

- 单篇笔记沿用 `作者-年份-短题.md`；年份待核时保留“年份待核”，不为整齐而猜年份。
- 已有文件名、专题目录和导图路径保持稳定；确需改名或迁移时，先修引用并保留恢复映射，不批量重命名。
- 文献、原始证据和仍有使用价值的阅读材料不因日期早而归档；只有被明确替代的旧稿、一次性汇报或失效入口才进入 `archive/`。
- 文献笔记中的判断仍属于个人阅读，不自动升级为主题结论、论点或实证结果。

## 七、论文阅读的卡片先行流程

2026-11-16用户确认：后续涉及论文阅读，先创建或复用精读论文卡片，再开展处理，以便复用。完整合同见[[项目管理/Hermes学术助手配置/论文精读卡片使用说明.md|精读卡片使用说明]]。

1. 确认来源身份，以DOI、Zotero父key或已核题名作者查同篇主记录；复用现有条目/PDF，保留父条目与附件key。缺附件就写“仅题录／仅摘要”，不能编造key或以建卡自动授权修改Zotero元数据。
2. 有卡则原位复用，保留路径、身份、格式、批注与实际核读范围；无卡先建立 `文献库/作者-年份-短题.md`，登记题录、来源、当前可读材料和未读范围，标为实际的初读/摘要初读、Partial。新卡用`nature-paper-card`的16节模板，但未核栏目明确待核读，不提前写精读。
3. 再进行本轮核读并更新同一卡片，只有具备相应核读证据后才开展方法/理论拆解、跨篇比较、写作引用等处理。定向阅读只补相应部分，不强制读全文；已有卡足以支持任务时直接复用。专题比较放 `文献库/专题精读/<专题>/`，回链卡片及原文定位。
4. 如需要导图，放入 `文献库/文献导图/<组>/`，说明它是阅读视图。
5. 运行 `literature_views.py --check`，确认索引同步、链接可解析。
6. 只有进入主题讨论或论文写作时，才在主题页、论点页或章节中引用；文献库本身不替它们下结论。

完整卡片的来源包、审计报告与必要核验记录沿用原专题证据目录，或放 `文献库/核读记录/<稳定短题或原有ID>/`，链接回单篇卡；支持文件不重复计篇，提取全文不是另一份原始来源。卡片结构检查不能证明全文精读或结论正确，主要图表、数字和论证仍需原文核验。本规则不触发全库历史补卡，不自动建立暂缓的上层研究问题映射。
