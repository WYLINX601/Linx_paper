## 打开并登录

1. 保持 Linux 开机、联网，Mac 与 Linux 的 Tailscale 在线。
2. 打开 [Neo4j Browser](http://100.68.38.32:7474/browser/)。
3. 连接地址填 `100.68.38.32:7687`，协议可用默认的 `neo4j://`，用户名为 `neo4j`，数据库为 `neo4j`。
4. 密码保存在 Mac 的私有文件 `/Users/wangyuelin/.config/neo4j-paper/access.json` 的 `password` 字段。该文件权限为600，仅当前用户可读写。密码没有写入 Obsidian 或本文档。

网页登录入口已实际打开；数据库凭据已通过 HTTP 和 Bolt 查询验证。浏览器中首次输入密码与点击 Connect 留给使用者，尚未在网页内完成登录后的图形操作。

## 第一次看什么

建议先看单独的“堂屋—前廊”演示。登录后，把下面一段粘贴到查询框并点击 Run；在结果中选择 Graph。

```cypher
MATCH (a:Entity:Demo)-[r]->(b:Entity:Demo)
RETURN a, r, b;
```

这组空间是虚构教学输入。它用于解释邻接、界面和通行如何表达，不能写成某座真实民居的调查结果。点击节点或边可以查看属性；空间通行边的 `qualifiers` 中保留界面和通行情境。

然后看独立的文献案例图：

```cypher
MATCH (a:Entity:Literature)-[r]->(b:Entity:Literature)
RETURN a, r, b;
```

更多示例见 [常用查询](常用查询.cypher)，共10段，逐段运行，包括周湖8号特征及来源、分类判据、堂屋与前廊通行、周湖1号争议证据图。这里的“文献案例”仍是文献材料试表达，不代表新增了现场实测。

## 数据库中有什么

| 内容 | 数量 | 含义 |
|---|---:|---|
| 文献领域实体 | 14 | 文献中的民居对象、记录、类型与方案等 |
| 演示领域实体 | 7 | 单独标记的虚构空间及界面等 |
| 断言记录 | 55 | 27条文献断言、28条演示断言；保留值、范围、归属与证据 |
| 分类判断 | 4 | 保留判据与结论；仅2条匹配结论投影成正向类型边 |
| 证据 / 来源 | 6 / 3 | 各自限定在所属数据集中 |
| 原始文件快照 | 5 | 模型、两组数据、优化依据、优化记录及SHA-256 |
| 数据库总节点 / 总关系 | 94 / 216 | 包含记录、证据和追溯结构，不等于94座建筑或216项建筑事实 |

**Obsidian 中的 JSON 仍是维护源，Neo4j 是它们的数据库表达。** 本次没有改变学术模型或扩充建筑事实；网页内编辑数据库不会自动写回 JSON。模型定义完整保存在快照中，目前没有把每个模型类、特征和约束都另建为可运行的本体节点，也没有增加自动推理引擎。映射细节见 [数据映射说明](数据映射说明.md)。

冲突证据用 `CONFLICTING_EVIDENCE`，支持证据用 `EVIDENCED_BY`。分类不匹配不会画成“属于该类型”；没有根据相邻关系推断可通行。

## 存储、网络和启动

- Linux 工作目录：`/home/linx/.local/share/neo4j-paper`；软件运行文件约504MiB，下载存档约344MiB。数据和本次备份很小，整个部署约0.85GiB，以验收记录为准。
- Mac 只增加少量脚本、文档、验收报告和私有凭据文件，没有安装大型软件。
- 用户服务名：`neo4j-paper.service`，已启用开机启动；系统原有用户后台运行设置 `Linger=yes` 已确认。已测试服务重启，未重启整台电脑。
- 服务仅监听 Tailscale 地址 `100.68.38.32` 的7474和7687端口，并启用数据库认证；未绑定校园网或公网接口。HTTP/Bolt 本身未启用TLS，跨机器传输依赖Tailscale加密隧道。
- 为修复浏览器502，在 Mac 的 Wi-Fi 代理例外中追加了单个地址 `100.68.38.32`。原例外列表备份在 `/Users/wangyuelin/.config/neo4j-paper/proxy-before.json`。其余代理设置保留。代理软件以后如覆盖例外列表，可能需要重新添加该地址。
- JVM最大堆768MiB，页缓存256MiB；服务总内存限制2300MiB。内存占用与磁盘占用是两回事。

## 日常维护

以下命令在 Mac 终端执行。正常使用只需浏览器，不需要运行这些命令。

```sh
# 查看服务状态
ssh linx-HP-EliteDesk-880-G6-Tower-PC 'systemctl --user status neo4j-paper.service --no-pager'

# 启动 / 停止
ssh linx-HP-EliteDesk-880-G6-Tower-PC 'systemctl --user start neo4j-paper.service'
ssh linx-HP-EliteDesk-880-G6-Tower-PC 'systemctl --user stop neo4j-paper.service'

# 手动备份：短暂停库导出，然后自动恢复运行并核对图谱
ssh linx-HP-EliteDesk-880-G6-Tower-PC 'python3 /home/linx/.local/share/neo4j-paper/tools/Linux备份.py'
```

已生成一次原生 `neo4j.dump` 备份，位置和哈希见 [备份与重启记录](验收/Linux报告/备份与重启.json)。备份包含图数据库、输入快照和无密码配置；不包含系统认证数据库。已读取归档元信息并验证服务重启后的查询，尚未进行异机恢复演练。当前没有设置定时备份。

图数据库dump另存了一份约110KB的[Mac副本](备份/neo4j-20261022.dump)，与Linux原件SHA-256一致；输入JSON仍在本项目中。

原论文PDF、Zotero附件和证据图片仍保存在Mac原资料库，未复制到Linux。数据库保存的是附件键、原路径、页序和证据记录，因此这份数据库备份不能代替Obsidian与Zotero资料的备份。

同一份输入重复导入不会重复创建节点或边。若输入文件内容变化，导入会因哈希不同拒绝覆盖；需要先设计版本迁移，不能直接把新内容强制写入当前版本。首次安装脚本也会拒绝覆盖已有部署。
