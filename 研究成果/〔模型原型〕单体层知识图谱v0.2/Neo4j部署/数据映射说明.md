# 单体层知识图谱 v0.2：Neo4j Community 5.26 导入映射

本目录提供标准库 Python HTTP 导入器、可复制的查询示例和本地 dry-run 自测。数据库目标是 Neo4j Community 5.26 的 `neo4j` 数据库，使用 HTTP Transactional API：`POST /db/neo4j/tx/commit`。导入器只写入 `kgv02:` 命名空间，不执行全库清空。

## 数据与身份

`模型定义.json`、`案例图谱.json`、`空间关系演示.json` 各自作为完整快照节点保存，节点属性含源文件 SHA-256 和完整 `rawJson`。本目录中存在的 `优化依据.json` 与 `优化记录.json` 也仅作为附加快照，不额外投影其记录。文献案例和虚构演示的实体、断言、来源、证据、分类记录分别使用独立 UID 前缀。

| 输入记录 | Neo4j 标签 | UID 示例 |
|---|---|---|
| 文献领域实体 | `KGItem:Entity:<原class>:Literature` | `kgv02:literature:entity:R_8` |
| 演示领域实体 | `KGItem:Entity:<原class>:Demo` | `kgv02:demo:entity:S_HALL` |
| 来源、证据、断言、分类 | `KGItem:<Source\|Evidence\|Assertion\|Classification>:<Literature\|Demo>` | `kgv02:literature:assertion:F_8_column_bay_form` |
| 完整输入快照 | `KGItem:ModelSnapshot`、`KGItem:DatasetSnapshot` 或 `KGItem:SupplementSnapshot` | `kgv02:model:snapshot`、`kgv02:literature:snapshot` |

所有节点使用统一的 `KGItem.uid` 唯一约束。领域实体保留 `datasetKind`、`sourceId`、`label/name`、原始 `class` 与记录级 `rawJson`。没有把属性值建成建筑实体，也没有将争议值扁平覆盖到建筑实体。模型和数据快照覆盖未投影的 `gaps`、`conflicts`、判据、规则及其他字段。

断言各自为 `Assertion` 记录节点。它保留 `scope`、`status`、`attribution`、`via`、记录时点、证据 ID 和完整原始 JSON。断言值用 `valueJson` 表示，所以 `false` 和 `null` 都有明确表达；同时以 `hasValue` 区分“没有 value 字段”和“value 为 null”。Neo4j 属性不能保存 null，故不会把 null 写成属性删除。嵌套的 `accessContext`、`derivedFrom`、冲突证据等以 JSON 字符串保留。

断言连到 `SUBJECT`、`OBJECT`、`EVIDENCED_BY` 记录关系；有 `via` 的记录再连 `VIA`。`conflictingEvidence` 单独投影为 `CONFLICTING_EVIDENCE`，不会与支持证据混用；完整输入仍保留在断言的 `rawJson`。证据通过 `FROM_SOURCE` 回到同一数据集的来源。对象型断言另建立原 predicate 命名的领域展示边，边上包含 `assertionId` 和 JSON 字符串 `qualifiers`。展示边只由输入中的对象断言生成，因此 `direct_access_to` 不会从 `adjacent_to` 或其他关系推断；文献数据也不会获得通行边。

分类记录保留决策、`criteriaResultsJson` 和原始 JSON，并连接 `SUBJECT`、`TYPE`、`SCHEME`、每条判据所引用的 `INPUT` 断言及 `EVIDENCED_BY` 证据。只有 `decision = criteria_match` 会额外生成 `has_type` 肯定展示边；`criteria_not_match`、`insufficient_evidence` 和 `author_assigned` 不会生成该边。分类记录本身仍完整保存，包括 `PROTO_8` 的四项判据。

`TypeConcept` 的源记录若含 `scheme`，实体属性也保留该字段，并投影为指向对应 `TypeScheme` 的 `in_scheme` 边；该边的 `sourceField` 与 `qualifiers` 明确标为 `node.scheme`，和由断言对象投影出的 `in_scheme` 边区分。

## 不覆盖规则

导入器先确保 `KGItem.uid` 唯一约束，再把每个命名空间快照的 UID 与 SHA-256 一起 `MERGE`。若同一 UID 已绑定不同源哈希，唯一约束会拒绝写入，整批数据事务回滚；不会静默覆盖旧版本。需要迁移或更改数据时应另行设计新命名空间和迁移。导入只 `MERGE` 自己的 UID，不清空或更新其他节点。

HTTP 调用用 Python 标准库，不依赖第三方包；通过空代理映射绕过系统代理，适合直接访问 tailnet 地址。HTTPS 使用系统证书校验。凭据文件只读取 `username` 和 `password` 字段，不打印或写入结果报告。Neo4j 返回 HTTP 200 但事务体含 `errors` 时，脚本仍会明确失败。

## 运行

本地先做无网络自测：

```sh
python3 '导入与验证.py' \
  --source-dir '..' \
  --output-dir '.' \
  --mode dry-run
```

Linux 部署时，将三份输入 JSON 放在 `input/`、脚本放在 `tools/`。父会话负责运行真实导入。对应命令如下：

```sh
python3 tools/导入与验证.py \
  --source-dir input \
  --endpoint http://100.68.38.32:7474 \
  --credentials-file ~/.config/neo4j-paper/access.json \
  --output-dir output \
  --mode import

python3 tools/导入与验证.py \
  --source-dir input \
  --endpoint http://100.68.38.32:7474 \
  --credentials-file ~/.config/neo4j-paper/access.json \
  --output-dir output \
  --mode verify
```

`access.json` 至少含 `{"username":"...","password":"..."}`。端点可写 HTTP(S) 根地址或完整 Transactional API URL。`import` 会提交约束与图数据两笔事务；完成后建议执行 `verify`。验证会逐个比较命名空间内节点的完整 `properties(n)` 与预期属性、`labels(n)` 与预期标签（包括快照标签），同时检查节点集合和关系多重集，重复边也会导致失败。完整属性比较涵盖 `rawJson`、`sourceHash`、`value`、`decision`、`datasetKind` 等投影字段，并拒绝额外属性或标签；报告分别给出节点数、比较的属性值数、标签节点数及标签总数、关系总数。关系按端点、类型、身份字段和 qualifiers 逐项计数，因此即便一条相同边重复出现也会报错。dry-run 不访问数据库，只生成 `导入自测.json`；真实运行结果写到 `最近运行.json`，都不含凭据。

## 本地验收边界

dry-run 核对 14 条文献实体、7 条演示实体、27+28 条断言、4 条分类、引用完整性和逐记录 JSON 往返；并检查两条演示通行断言都有界面与情境、文献没有通行断言、只有两条肯定类型边、`PROTO_8` 不形成肯定类型边，以及 `F_1_roof_layered` 的争议值、支持证据和冲突证据分别留存。另核对分类判据引用的输入断言以及冲突证据使用独立关系。独立的本地无网络模拟中，正确 fixture 通过；在 `rawJson` 不变时篡改投影 `value`、删除一个演示节点的 `Demo` 标签、复制一条相同关系，三种情况均应被拒绝。模拟不连接数据库。只有父会话在 Linux 上的 `import` 与 `verify` 输出能证明远程 Neo4j 状态。
