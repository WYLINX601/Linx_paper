# 传统民居建筑形态本体定义总表（V1.0 候选）

**状态先说清楚：** 本表是供第3.3.2—3.3.4节写作、评审和后续迁移使用的**候选工作 Schema**，不是已经写入 Neo4j 的数据库 Schema，也不是 BOT 的新增原定义。表中“已实现”只指 V01 合成原型或既有规则中已有对应表达；“拟新增”“未实施”均表示尚未建标签、未建关系、未迁移数据。文档完成不等于本体已形式化、数据库已更新或真实样本已验证。

## 1. 使用边界与来源

- **上位标准：** [BOT基准](BOT基准.md) `BOT-B0.1` 的 `bot:Site`、`bot:Zone`、`bot:Building`、`bot:Space`、`bot:Element`、`bot:Interface` 及相应对象属性。
- **本研究规则：** [本研究优化基准](本研究优化基准.md) 的 U01—U18；其中 U18 规定 L2—L3 外部形态强制启用、仅 L3 内部形态条件启用、缺口显式标注。
- **现有实现：** [V01统一原型](../〔合成试例〕虚拟民居单体试验V01/案例模型.json) `V01-unified-2.2`。现行标签为 `Building`、`Zone`、`Space`、`Element`、`Interface`、`Courtyard`、`RoofSurface` 等；本表提出的是领域类名，落地时需要显式映射或双标签，**不得直接把旧库标签改名后声称迁移完成**。
- **关系复用情况：** `BOT_HAS_BUILDING`、`BOT_HAS_SPACE`、`MEMBER_OF_ZONE`、`BOUNDARY_PARTICIPANT`、`INTERFACE_OF`、`DIRECT_ACCESS_TO`、`HAS_SOURCE` 已在 V01 中实际使用；`LOCATED_IN_ADMIN`、`HAS_HISTORICAL_VILLAGE`、`USES_CHUANDOU_PATTERN`、`CLASSIFIED_BY`、`REGULATED_BY_CLAUSE` 为拟新增或仅有规则定义，V01 尚未实例化。

## 2. 核心类定义表（对应 3.3.2）

| 知识维度 | 本体类名（拟用 Neo4j Label） | 上位标准复用与仓库基准对应 | 建筑学界定与样本边界 | 启用层级 | 实施状态 |
|---|---|---|---|---|---|
| 空间聚落与样本容器 | `:VillageUnit` | 扩展 `bot:Site`；行政与历史聚落单元 | 区分现行行政村与历史自然村寨，承载 2019 年并村映射；不与建筑实例混同 | L1—L3 全覆盖 | 拟新增；可由现有 `Zone` 扩展或双标签 |
| 院落与宅院组团 | `:ClusterZone` | 复用 `bot:Zone`；对应 V01 整体 `U01` | 由单栋或多栋民居、院墙与台地共同构成的山地宅院组团范围 | L2—L3 全覆盖 | 复用 `Zone`；V01 有同类对象，未改标签 |
| 核心建筑实例 | `:VernacularHouse` | 复用 `bot:Building`；对应 V01 的 `B01/B02` | 传统居住建筑，含“宅祠合一”老宅及主体构架可辨的微改老宅 | L2—L3 核心样本 | 复用 `Building` 语义；拟新增领域标签或双标签 |
| 非样本参照实体 | `:EnvNode` / `:ContrastModernBuilding` | 扩展 `bot:Zone` / `bot:Building`；排除出统计分母 | 前者存独立宗祠、寺庙、廊桥等环境节点；后者存安置新村砖混房与新建仿古建筑 | 仅关联参照 | 拟新增；不计入民居样本 |
| L-I 外部过渡与院落空间 | `:CourtyardSpace` | 复用 `bot:Space` ＋ `ExternalTransition`（U14） | 天井、前坪、檐廊下灰空间及接地错台外部空间 | L2—L3 全覆盖 | V01 有 `Courtyard`／`ExternalTransition`，可映射 |
| L-II 室内平面空间单元 | `:PlanSpace` | 复用 `bot:Space`（U02／U15） | 明间堂屋、次间卧室、厢房、披屋及现代介入的厨卫空间单元 | 仅 L3 有图／入户启用 | 拟新增；L2 及无资料样本标缺口 |
| L-III 穿斗构架与侧样 | `:TimberFrame` / `:ChuandouPattern` | 扩展 `bot:Element` ＋ D02 侧样形式分离规则 | `TimberFrame` 表征单栋实物木构架；`ChuandouPattern` 表征可跨村共享的侧样排架母型，区分实物、侧样图与抽象排架形式 | 仅 L3 有图／入户启用 | 拟新增；未实例化 |
| L-IV 围护与界面要素 | `:EnvelopeElement` / `:SpatialInterface` | 复用 `bot:Element`、`bot:Interface` 及 `RoofSurface`（U02／U04） | 屋顶坡面、夯土／木板壁／乱石外墙、台基，以及院门、门窗开口界面 | L2—L3 全覆盖，细部随证据深化 | V01 有 `Wall`、`RoofSurface`、`Interface` 等，可映射 |
| 分类方案与抽象类型 | `:ClassificationScheme` | 复用 U14（G06）分类方案节点 | 管理山地合院、一字形廊屋、“寮”制等形态类型判据与规则版本 | 模式层全局共享 | 规则已定义；V01 未建该标签 |
| 保护管控条款 | `:ProtectionClause` | 扩展规则规范类；拆解自导则与规划文本 | 绑定适用保护等级与目标部位的最小颗粒度保护修缮要求条款 | 规则层全局共享 | 拟新增；未实例化 |
| 多模态证据源 | `:EvidenceSource` | 复用 `prov:Entity` ＋ V01 的 `Source`（U10／U13） | 法定规划文本／图则、学术论文与测绘图、方志宗谱、无人机三维与现场照片 | 实例与关系级强制绑定 | V01 有 `Source`／`SyntheticSource`；真实来源待建 |

## 3. 核心对象属性定义表（对应 3.3.3）

| 关系名称（拟用 Edge Type） | 定义域（起点） | 值域（终点） | 基准溯源与语义约束 | 回应能力问题 | 实施状态 |
|---|---|---|---|---|---|
| `LOCATED_IN_ADMIN` / `HAS_HISTORICAL_VILLAGE` | `:VernacularHouse` 或 `:ClusterZone` | `:VillageUnit` | 分别连接现行行政村与 2019 年并村前自然村寨／方志旧称，严禁混用覆盖 | CQ1 异名消歧 | 拟新增 |
| `BOT_HAS_BUILDING` / `BOT_HAS_SPACE` | `:ClusterZone` 或 `:VernacularHouse` | `:VernacularHouse` / `:CourtyardSpace` / `:PlanSpace` | 严格沿用 `BOT-B0.1` 与 `U03/U15` 区域与空间包含关系，不替代构件组成 | CQ2 形态组合 | V01 已实现（`BOT_HAS_BUILDING` 2 条、`BOT_HAS_SPACE` 5 条） |
| `MEMBER_OF_ZONE` | `:EnvelopeElement` 或 `:TimberFrame` | `:VernacularHouse` 或 `:ClusterZone` | 沿用 `U03/U15` 建筑成员归属关系；未知三维几何时不硬推 `containsElement` | CQ2、CQ4 | V01 已实现（15 条） |
| `BOUNDARY_PARTICIPANT` | `:CourtyardSpace` 或 `:PlanSpace` | `:VernacularHouse` / `:EnvelopeElement` | 沿用 `U03/U14(G03)/U17`，边属性记录局部边段 ID 与围合参与角色 | CQ2 院落组团围合 | V01 已实现（28 条） |
| `INTERFACE_OF` / `DIRECT_ACCESS_TO` | `:SpatialInterface` / `:PlanSpace` | 空间或宿主墙体／相邻通行空间 | 沿用 `U04/U07/U14(G04)`，表达院门、堂屋、次间与厨卫披屋的中轴流线连通 | CQ2、CQ4 微改诊断 | V01 已实现（`INTERFACE_OF` 25 条、`DIRECT_ACCESS_TO` 5 条） |
| `USES_CHUANDOU_PATTERN` | `:TimberFrame` | `:ChuandouPattern` | 将 L3 实测木构挂载至标准穿斗“侧样”排架形式，构建跨村同构二部子图 | CQ2、CQ5 同类实例参照 | 拟新增；未实例化 |
| `CLASSIFIED_BY` | `:VernacularHouse` 或 `:CourtyardSpace` | `:ClassificationScheme` | 沿用 `U14(G06)`，边属性记录类型名称（如泥瓦寮、三合院）、判据版本与审核状态 | CQ2、CQ5 | U14 规则已定义；V01 未建边 |
| `REGULATED_BY_CLAUSE` | `:VernacularHouse` 或各形态部位节点 | `:ProtectionClause` | 按建筑法定保护等级将院落、体量、木构、屋面、外墙、门窗约束直接连向部位 | CQ4 部位条款匹配 | 拟新增；未实例化 |
| `HAS_SOURCE` | 任意实例节点（同时关系边内嵌 `sourceUid`） | `:EvidenceSource` | 沿用 `U13/U14(G05)`，属性强制携带 `fields`、`locator`（页码／图号）、`evidenceStatus`（四态） | CQ1、CQ3 账实冲突与缺口 | V01 已实现（57 条，均为合成来源） |

**边属性最低要求：** 关系断言须能回溯到 `sourceUid`、`fields`、`locator`、`sourceVersion` 与 `evidenceStatus`。没有来源定位的边只能作为候选或派生结果，不能冒充实测事实。

## 4. 核心数据属性与量化口径表（对应 3.3.4）

严格执行 `U13`“尺寸直接归对象、不另造尺寸占位节点”与李仁渊（2020）“称谓—姓氏—形态分列”原则。下表是候选字段与采集口径，不是已冻结的数据字典；字段名落地时需与 V01 现有字段做映射。

| 挂载对象类 | 属性字段名 | 数据类型与单位 | 建筑学采集与计算口径 | 义务等级（依 U17） | 实施状态 |
|---|---|---|---|---|---|
| `:VernacularHouse`（身份与外轮廓） | `houseId` / `sampleTier` | String（枚举 `L2` / `L3`） | 唯一实例主键，与 `L/E/D` 编号严格区分 | L2/L3 必填 | 拟新增；V01 用 `uid` |
| 同上 | `villageDesignation` / `householdLineage` | String | 分列记录“村落名录背书”与“住户姓氏／族属线索（蓝／雷／钟／汉姓共营等）”，不与建筑类型混写 | 有据必填，无据标 `待核` | 拟新增 |
| 同上 | `protectionGrade` | String（受控枚举） | `文物建筑`、`历史建筑`、`传统风貌建筑`、`未定级` | L2/L3 必填 | 拟新增 |
| 同上 | `footprintArea` / `mainAzimuth` | Float（$\text{m}^2$ / 度） | 基底投影面积 $S_{\text{foot}}$ 与主朝向方位角 $\theta \in [0^\circ, 360^\circ)$，注明 `measurementBoundaryBasis` | L2/L3 航测或图纸提取 | 部分可由 V01 几何字段映射 |
| `:ClusterZone` / `:CourtyardSpace` | `microTopography` / `groundingMode` | String（受控枚举） | 五类微地形梯度＋顺等高线平列／垂直跌落／依山筑台吊脚或错台接地 | L2/L3 必填 | 拟新增 |
| 同上 | `slopeAngle` / `terraceDrop` / `courtyardRatio` | Float（度 / $\text{m}$ / 无量纲） | 基地坡度 $\alpha$、台基高差 $\Delta H_{\text{base}}$、院落基底占比 $R_{\text{yard}}$（按 `U15` 声明切片窗口） | 具备点云／剖面时计算 | 拟新增；需几何来源 |
| `:PlanSpace`（L-II 内部平面） | `bayCount` / `planWidth` / `planDepth` / `planAspectRatio` | Int / Float（间 / $\text{m}$ / 无量纲） | 开间数、总面阔 $W$、总进深 $D$ 及平面宽深比 $R_{\text{plan}} = W/D$（依 `D02` 区分间数与房间数） | **L3 条件项**；L2 标 `档案缺口` | 拟新增；未实例化 |
| 同上 | `kitchenBathIntervention` | String（枚举） | `无现代介入`、`披屋附建`、`次间局部切分`、`侵占明间堂屋中轴`、`未知(档案缺口)` | **L3 条件项**；L2 标 `档案缺口` | 拟新增；未实例化 |
| `:TimberFrame` / `:ChuandouPattern` | `groundPostCount` / `purlinCount` / `shortPostCount` | Int（柱／檩数） | 落地柱数 $N_{\text{post}}$、檩数 $N_{\text{purlin}}$、骑童柱（瓜柱）数（如五柱七檩） | **L3 条件项**；L2 标 `档案缺口` | 拟新增；未实例化 |
| 同上 | `stepSpanPattern` / `corridorFrameType` | String | 步架净距序列（$\text{m}$）与前后廊轩构架做法（对齐赵潇诺侧样分型与 `D02` T01/T02） | **L3 条件项**；L2 标 `档案缺口` | 拟新增；未实例化 |
| `:EnvelopeElement`（L-IV 屋面外墙） | `roofForm` / `roofMaterial` / `wallMaterial` | String（多标签保留来源） | 双坡悬山／硬山；小青瓦／彩钢瓦等；夯土墙／木板壁／乱石砌墙（依 `U08` 区分表层与墙芯） | L2/L3 必填（墙芯未知标未知） | V01 有材料标签；字段名待映射 |
| 同上 | `eaveHeight` / `ridgeHeight` / `roofElevRatio` | Float（$\text{m}$ / 无量纲） | 檐口高 $H_{\text{eave}}$、屋脊高 $H_{\text{ridge}}$ 及立面屋身比 $(H_{\text{ridge}}-H_{\text{eave}})/H_{\text{eave}}$（绑定 `USES_DATUM`） | 有图纸或无遮挡点云时提取 | 拟新增；V01 有邻近字段 |
| `:ProtectionClause` 与溯源边 | `actionPolarity` / `evidenceStatus` / `exactQuote` / `locator` | String | 管控极性（禁止拆改／风貌协调／允许微改）；四态证据状态；逐字原文引句；精确页码或图号 | **全局强制必填（零幻觉硬约束）** | 拟新增；未实例化 |

## 5. 与 V01／Neo4j 的迁移边界

现行 V01 的标签与关系命名不是本表的子集，两者需要显式对应：

| V01 现行标签／关系 | 本表候选类／关系 | 处理建议 |
|---|---|---|
| `Building` | `VernacularHouse` | 先双标签或映射查询，不直接改名；需核对“民居”语义过滤 |
| `Zone` | `VillageUnit` / `ClusterZone` | 按对象尺度拆分；同一 `Zone` 不自动兼作行政村与宅院组团 |
| `Space` / `Courtyard` / `ExternalTransition` | `CourtyardSpace` / `PlanSpace` | 按外部院落与室内平面分列；未知平面不补造 |
| `Element` / `Wall` / `RoofSurface` | `EnvelopeElement` | 保留原构件标签，领域类作为上位或双标签 |
| `Interface` / `EntranceInterface` | `SpatialInterface` | 保留角色边，不把界面改造成空间 |
| `Source` / `SyntheticSource` | `EvidenceSource` | 真实来源与合成来源分开，不因同名混用 |
| `MEMBER_OF_ZONE` / `BOUNDARY_PARTICIPANT` / `INTERFACE_OF` / `HAS_SOURCE` | 同名关系 | 已可复用；迁移时保留原边 UID 与属性 |

**未执行事项：** 本轮没有创建新标签、没有新增关系、没有迁移 V01、没有写 Neo4j、没有运行 Protégé 一致性检验。上述迁移建议须在第3.4.2节形式化检验和第4.4节存储实施时另行授权与核验。

## 6. 待审核与验证

1. 核心类是否覆盖第5章的分析任务，是否存在应合并或应拆分的类。
2. 对象属性的定义域／值域与基数是否与 BOT 语义一致；`CLASSIFIED_BY`、`REGULATED_BY_CLAUSE` 的边属性是否足够。
3. 数据属性的单位、取值枚举、义务等级与缺失／未知／不适用规则是否可执行。
4. 能力问题集（CQ1—CQ5）能否由本表覆盖；不能覆盖的部分标明缺口，不强行补类。
5. 形式化（OWL／Protégé）后是否出现类阶或属性冲突；本表当前未做此检验。
