## 本轮每项拆了什么

保留原编号、模块、分析对象、原研究内容及全部依据；新增：

- 主要去向：本体与数据为主、分析为主、兼有、研究与证据规则。
- 研究角色：语义定义、事实记录、派生判断、分析目标、研究与证据规则。允许多角色。
- 本体与数据候选：对象、属性/记录字段和关系的候选表达，不直接等于新类或原子字段。
- 数据依赖：引用原条目编号及具体所需字段；通用证据规则贯穿所有条目。
- 派生过程：有适用计算/判断时记录输入规则、输出和门槛；无充分判据不编公式。
- 分析体系：问题、方法、结果形式与解释边界。
- 拆分理由：说明为什么如此归类，而非只贴标签。

“核心候选、条件深化、关联解释、待补核专题”等原采用建议完整保留，与本轮角色不是同一维度。分析结果可以回写，但必须保存来源、方法及输入版本。

## 维护与追溯

[衔接拆解.json](衔接拆解.json)是本衔接稿的唯一结构化维护源，其中`original`逐行保存原CSV内容；Markdown、CSV和导图均为派生阅读视图。原框架的维护源仍是[原研究内容总表CSV](../〔候选框架〕建筑单体研究内容框架v0.1/研究内容总表.csv)，没有被本稿替代。

原依据可回到[文献依据索引](../〔候选框架〕建筑单体研究内容框架v0.1/文献依据索引.md)。本轮未重新阅读全文；新增角色、依赖及规则均为研究者衔接建议，不将它们表述为原作者已提出或已实施的方法。

重生成阅读文件使用`生成阅读视图.py`；它只生成新目录内阅读文件和库外临时导图输入。已有导图修改必须遵循obsidian-mindmap技能的指纹校验与原子编辑流程，不能用create覆盖旧图。`核验衔接.py`检查编号顺序、原行保留、输入引用、派生记录、视图内容、链接、原文件指纹和四张原生图。

原框架、原生导图和现有v0.2图谱文件的操作前指纹保存在[原文件指纹](原文件指纹.json)。本轮未主动编辑原文件，不写Neo4j，不迁移正式模型；完成阶段检测到一处原导图保存差异，原指纹保留且未回滚，详见主会话记录；总体研究主线和阶段未变，现有研究路径图保持原样。后续正式采用导致方案变化时另行同步图源及PNG。
