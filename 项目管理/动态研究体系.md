# 动态研究体系：设计与使用

## 本轮决定与边界

用户在讨论中确认：论文大纲应能随研究调整，研究路径可用Mermaid表达；主题需要体系设计、研究方法、操作方法等角色标签，并授权设计和更新研究库。本方案落实这种组织方式，不重写研究定位、正文、证据和模型数据。

**研究问题与证据驱动大纲，而不是让目录或文件数量代替研究判断。**章—节层级可调整；研究主题、证据和成果按职责复用；文件路径尽量稳定。生成脚本由显式命令运行，没有安装后台监控，也不会在保存后自动改正文或数据库。

## 维护位置：一个事实只改一处

| 内容 | 唯一维护位置 | 派生展示 |
|---|---|---|
| 用户确认的研究定位、范围与约束 | `context/PROJECT_CONTEXT.md` | 大纲及路径引用，不复制成新研究决定 |
| 当前上层研究问题与暂缓映射状态 | 研究路径JSON的`research_questions` | `论文章节/研究问题.md`及当前论证索引、关系JSON |
| 主题问题、判断、依据、缺口 | 各主题的`〔主角色〕主题名.md`（`type: research-topic`） | 章节引用 |
| 主题主要角色与辅助角色 | 主题页frontmatter的`research_role`、`research_roles_secondary` | 角色卡、标签、目录前缀、成果入口 |
| 章节顺序、小节、论证任务、主题采用、状态 | `论文章节/大纲结构.yaml` | 现行大纲、章节导航、Mermaid结构图、采用记录及反向索引 |
| 研究环节、依赖与反馈 | `研究成果/〔研究路线〕论文研究路径/研究路径结构.json` | 研究路径工作图及环节说明 |
| 成果归属、用途、主源与边界 | 各成果包README的`artifact_*`字段 | 主题成果表及成果总入口 |
| 正文、案例、定义、实验与原始证据 | 各自既有主源 | 不由本轮脚本改写 |

本轮将原来在章节表中手工维护的采用关系迁入大纲结构；原表转为派生视图。**不再同时编辑YAML和章节采用表。**成果关系仍沿用既有README主源，未另建第二套成果登记。

**2026-11-09问题层接续：** 新方向的四个上层问题已从旧主题内网络分开。当前问题骨架没有推定连线，逻辑角色与下层映射留空；既有主题内关系独立保留。旧大纲、章节采用和详细框架图尚未按新问题重构，不因生成问题视图就声称其已适配。问题题名只在路径JSON声明一次，路径节点引用稳定问题身份，避免复制维护。**2026-11-17：** Notion V3.3已落库，现行大纲改为建筑形态—领域本体—知识图谱—知识发现六章；1.5.1 V0.1已提出核心问题与四个子问题并同步到路径JSON，2026-11-08旧四问保留为历史工作问题，待1.3综述定稿后作最终语义收口；旧框架图与主题命名尚未按新定位重画或迁移。

## 主题角色

- **研究界定**：对象、范围、纳入与排除。
- **理论与文献依据**：已有认识、借鉴与缺口。
- **体系设计**：对象、信息和关系如何组成整体。
- **研究方法**：如何获得认识及其理由、判据。
- **操作方法**：如何执行、记录、复核。
- **检验与评价**：如何判断有效性及适用边界。

一个主角色、若干辅助角色，沿用前一轮讨论的角色分配；2026-11-04检验类两主题合并后为七主题。主角色前缀同时进入主题目录及主文档名称；`topic_title`保留不带前缀的逻辑名，`wiki_id`保留稳定身份。辅助角色只用于属性与检索。`研究角色/…`标签由角色字段生成；主题角色可以调整，不意味着研究完成或章节归属固定。“操作方法”目前主要作为辅助角色，不为凑齐分类新建空主题。

## 动态大纲如何调整

`chapters`列表顺序决定章号，章内`sections`列表顺序决定节号。`id`是稳定身份，不能因重排改ID；文件夹前面的数字只是旧路径，不再决定显示顺序。

二级节可选用`subsections`维护三级标题，其顺序决定三级编号；三级节点也有稳定`id`、`included`、`title`、`purpose`、`status`和`change_note`，通过`origin_chapter_path`保留原章入口。三级主题采用沿用父节，不重复计入采用关系；父节停用时三级不展示但锚点保留。当前第二至第四章按论证需要展开三级标题；第三章归并图谱方法，第四章按样本—数据—构建—结果组织，不要求各章标题数量相同。`outline_focus`与`logic_chain`维护当前整理重点和全文逻辑；章级`argument_flow`与`handoff`分别说明章内顺序和向后交付，全部由同一YAML生成展示。

- **改名**：修改`title`，保留ID；导航和结构图会同步，正文不会偷偷改名。
- **重排**：调整列表位置；显示编号重算，正文接续仍指向原稿。
- **跨章移动一节**：移动完整节对象，保留ID、采用关系、状态和来源编号。
- **新增**：分配从未使用过的ID，写明论证任务、主题、状态与变更理由。新章节需指定稳定导航路径及正文接续来源。
- **停用**：设`included: false`，不删除证据。停用章节保留入口，停用小节保留稳定锚点；不计入现行采用关系。
- **拆分或合并**：不要把不同论证任务冒充同一个ID。旧节点停用；新节点使用新ID，并在`change_note`记录接续关系和理由。

首次动态机制接续了v0.6的六章结构。本轮经授权修订论证任务，并新增独立方法／实施位置；现行规模由主源动态计算，不作为代码限制。每节新增`question`、`evidence_required`和`completion_gate`，分别说明问题、所需证据与完成判据；这些是工作要求，不是已完成声明。旧正文与原稳定ID继续保留，详见[[项目管理/学术大纲与角色命名修订说明.md]]。

## 实际更新命令

在Mac学术Python环境运行：

```sh
python /Users/wangyuelin/Desktop/Obsidian/Paper/项目管理/健康检查/research_structure.py --check
```

`--check`只读检查一致性，检测到过期视图返回非零。更新时改主源，再用同一脚本的`--output-dir <Paper库外工作目录>`生成候选文件。审核差异后，以每个目标的最新SHA通过mac-paper发布；冲突重新读取，不强行覆盖。再次运行`--check`确认同步。

日常可以直接告诉助手“把某节移到某章／调整某主题的角色”，由助手执行同一流程；不要求用户手工编辑全部派生文件。没有自动改研究判断、自动升格成果或自动迁移数据库的行为。

统一入口：`paper-maintain check` 检查全部派生视图与测试，`paper-maintain sync`／`--apply` 生成并发布视图，`paper-maintain doctor` 运行全库健康报告。结构变更先写计划，用 `outline-ops apply-plan ...` dry-run，确认后再 `--write`；结构工具只执行已确认的移动、改名、重排、停用和字段设置。

## 检查与恢复

验证ID唯一、主题存在、依赖无环（反馈边另算）、角色合法、主源存在；测试重排、新增、停用、跨章移动及角色变更的传播。研究结论与实证状态仍须人工核对。

替换已有文件通过mac-paper保存备份及读回。新增导航和角色字段可能触发原有字节依赖提示；不为“归零”刷新研究基线。旧原生导图中的失效链接另列，不把本轮图表成功渲染当成全库无错误。

## 文件树命名与显式迁移

- 主题目录及主文档：`〔research_role〕topic_title`；主题以frontmatter的`type: research-topic`发现，不再按固定文件名寻找。
- 成果目录：`〔artifact_label〕artifact_title`；包内README、代码、数据和附件保留原名。产物类型前缀不表示已完成或原创贡献。
- 改主要角色／产物类型前，生成逐路径映射与备份；迁移后更新大纲、关系主源中的真实路径、链接、脚本、原生导图linkdata，再生成派生视图并核验。
- `research_structure.py --check`会拒绝属性与实际名称不一致，不后台重命名。研究角色标签仍由属性派生。
- 路径变更只重映射依赖基线的路径键，不刷新旧SHA，不因此宣称证据已复核。
