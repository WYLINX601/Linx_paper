# 健康检查使用说明

> **2026-11-17环境修复：** 各生成器与`paper-maintain.py`已统一使用脚本相对根目录`Path(__file__).resolve().parents[2]`，不再依赖旧的`/Users/wangyuelin/Desktop/Obsidian/Paper`；macOS `._`伴生文件在读取与计数时跳过。依赖见`requirements.txt`（PyYAML、ruamel.yaml）。`paper-maintain check`已通过outline/alignment/claims/artifacts/literature/materials/tests全部检查。以下旧绝对路径命令保留为历史示例，当前请使用`paper-maintain`包装器或在本库根目录运行对应脚本。

## 运行

检查器只读，输出必须在Paper之外；结果经mac-paper写回本目录，不自动修复或更新基线。Python环境需要PyYAML与ruamel.yaml（安装：`python -m pip install -r 项目管理/健康检查/requirements.txt`）。

```sh
/Users/wangyuelin/.hermes/profiles/academic/runtime/venv/bin/python "/Users/wangyuelin/Desktop/Obsidian/Paper/项目管理/健康检查/wiki_health.py" --root "/Users/wangyuelin/Desktop/Obsidian/Paper" --output "/Users/wangyuelin/.hermes/profiles/academic/workspace/wiki-health-latest.json" --baseline "/Users/wangyuelin/Desktop/Obsidian/Paper/项目管理/健康检查/依赖基线.json"
```

基线只表示文件内容指纹建立，**不表示证据判断已重新审核**。真正核对后才更新对应依赖；初次没有基线时明确报告未知。输出时间与研究事实时间分开。

## 自动检查与人工边界

确定性检查涵盖文件目标、附件、中文空格路径、同名歧义、标题/块/HTML锚点、YAML、JSON、draw.io XML、重复wiki_id、章节覆盖、入口可达、依赖内容变化和替代循环。原生导图按linkdata检查，并另用已安装插件读取函数验证。

来源快照的站点脚本和外部资源缺失按离线限制报告，不改写来源。Zotero与外链、研究判断充分性、未登记派生关系、实证有效性、语义矛盾仍需相应任务核查。全库没有自动可信评分和自动合并。

运行test_wiki_health.py测试已知错误检出、合法文件不误报、mtime/内容变化区别及只读稳定性。检查器没有命令执行、网络访问或Paper写入分支；输出检查结果不等于研究通过验证。

## 统一维护入口（P0）

```sh
python "/Users/wangyuelin/Desktop/Obsidian/Paper/项目管理/健康检查/paper_maintain.py" check
python "/Users/wangyuelin/Desktop/Obsidian/Paper/项目管理/健康检查/paper_maintain.py" sync
python "/Users/wangyuelin/Desktop/Obsidian/Paper/项目管理/健康检查/paper_maintain.py" sync --apply
python "/Users/wangyuelin/Desktop/Obsidian/Paper/项目管理/健康检查/paper_maintain.py" doctor
```

- `check`：运行全部派生视图 `--check` 和测试，只读；不把 `wiki_health` 的存量历史问题当作本次阻塞。
- `sync`：在 Paper 外生成全部派生视图，列出变化；确认后加 `--apply`，逐个经 `mac-paper` 按当前 SHA 写回。
- `doctor`：运行完整 `wiki_health` 报告并显示错误／复核／信息计数；默认只报告，`--strict` 才在存在 error 时返回非零。
- 所有命令默认不后台运行，不自动改正文、证据或数据库。

## 结构操作（P1）

### 当前研究问题与暂缓关系检查

2026-11-09起，上层问题由研究路径JSON中的`research_questions`维护；`research_questions.py`负责校验与渲染，`research_claims.py`同时生成当前问题入口和独立保留的既有主题局部关系。`research_structure.py --route-only --check`可只读核对当前问题骨架，不扫描或重写下层主题与成果；不等同全库检查。

`logic_status: pending-discussion`及`association_status: deferred`下，问题间边、逻辑角色以及主题、子问题、论点、章节、成果映射必须为空。生成器拒绝悄悄沿用旧关系。新回归测试为`test_research_questions.py`；题名修改应同步传播到问题页、索引、关系数据和工作图。

```sh
python "/Users/wangyuelin/Desktop/Obsidian/Paper/项目管理/健康检查/outline_ops.py" validate
python "/Users/wangyuelin/Desktop/Obsidian/Paper/项目管理/健康检查/outline_ops.py" apply-plan plan.yaml
python "/Users/wangyuelin/Desktop/Obsidian/Paper/项目管理/健康检查/outline_ops.py" apply-plan plan.yaml --write
```

默认是 dry-run，`--write` 才通过 `mac-paper` 写入大纲主源。支持 `add`、`move`、`reorder`、`rename`、`retire`、`set`；稳定 ID 不因编号变化而改变。单节点命令 `move / rename / reorder / retire / set` 可用；`add` 建议用计划文件，避免字段不完整。

计划示例：

```yaml
id: 2026-11-04-example
operations:
  - op: add
    id: section-example
    parent: chapter-3
    as: section
    fields:
      title: 示例父节
      purpose: 说明其论证任务
      status: 工作结构；正文待补
  - op: move
    id: section-3-village
    under: section-example
    as: subsection
assertions:
  counts: {chapters: 6, sections: 35, subsections: 20}
```

`outline_ops.py` 只校验结构、ID、层级和计划断言，不判断章节论证是否成立。写入后运行 `paper_maintain.py sync --apply` 更新派生视图。
