# 院落文献成果示例：生成与维护

## 维护源与组织原则

- 唯一内容维护源：[拆解主源.json](../../研究成果/〔案例拆解〕敕木山村资料与对象拆解/拆解主源.json)的`courtyard_pilot`，当前0.3。原`papers/objects/relations`、旧材料编号及资料索引保持原职责。
- 本例提取作者已有的形制、特征和空间组织成果；类型允许只有名称与出处，案例与参数按实际材料逐步补充。作者成果、图注与阅读者图像说明分别归属。
- `findings`保存综合成果，`nodes/relations`组织类型、特征与联系，`evidence`保存原文定位，`image_notes`集中维护图片作用与局部观察，`cases`保留文献案例。`views`只是阅读主题和页面排版。
- [交互页面](../../研究成果/〔案例拆解〕敕木山村资料与对象拆解/院落与外部空间审核.html)与[文字说明](../../研究成果/〔案例拆解〕敕木山村资料与对象拆解/院落试例说明.md)均为同源生成视图。保留旧HTML文件名以接续链接，页面内容已转为成果导向。
- [生成器](generate_courtyard.py)和[模板](courtyard_template.html)负责本例；首轮素材主表与Excalidraw仍由原生成器维护，不是本例的第二份维护源。

## 输入与生成

先运行`mac-paper status`、`mac-paper context`并读取当前规则。用`mac-paper download`取得当前主源、原图及其provenance，暂存于academic档案scratch。

1. 当前拆解主源JSON。
2. 主源原素材路径下的`M008-F08.png`、`M008-F09.png`、`M008-F10.png`、`M008-F12.png`及各自下载生成的`.provenance.json`。生成器检查原路径与字节SHA。
3. 可选的逐页摘录：`PIW7KR8U-selected.txt`（PDF1—2页）、`VQRBWRBF-selected.txt`（PDF3—4页）；页头采用`=== PDF 1 ===`形式。对应Zotero附件`N9ALJ8SM`、`DAJ6JURK`。先核PDF哈希，再提取对应页；引文匹配按具体PDF页检查，跨页续段显式标注。

命令接口（占位路径需替换为实际暂存目录）：

```sh
python generate_courtyard.py --source /暂存目录/当前主源.json --images-dir /暂存目录/素材 --output-dir /暂存目录/生成结果 --evidence-text-dir /暂存目录/摘录
```

默认使用脚本旁的模板；另置模板可用`--template`指定。生成器使用Python标准库，产出HTML、Markdown和`build-checks.json`，不自动写Paper或数据库。HTML内嵌数据与图像，无CDN依赖，可直接离线打开。

## 检查与发布

- 核对转述、作者归属、原文定位和图片作用；这是提取质量检查，不是重新验证作者成果。保留原称谓和量词，综合结论不拆成无关联名词。
- 检查ID、来源、端点、主题覆盖、图片说明链接、按页引文和素材provenance；类型不以具名实例、完整字段或三维对应为接纳门槛。
- 实际浏览三个主题，检查选择、来源展开、图片加载与放大、键盘、缩放及窄屏。Markdown实际渲染检查；浏览器Markdown预览不表述为Obsidian原生渲染验收。
- 独立子任务承担限定的定向成果提取，主会话负责取舍、整合与页面验收。保留其实际输入和报告；不将旧版独立审核覆盖冒称为新版审核。
- 更新前保存旧版原件；对已有文件重新读取并使用最新SHA经`mac-paper upload --expected-sha256`写回，新文件用`--expect-missing`。冲突时重新合并；结果不明先读回，不盲目重试。
- 更新成果入口和归档索引，核对发布后主源与生成结果一致。程序通过不等于实证完成。本例不自动修改D03、双基准、V01、Zotero或Neo4j。

实际阅读、独立提取、生成与页面检查见[执行记录](../../研究成果/〔案例拆解〕敕木山村资料与对象拆解/院落试例核验.json)；0.2原件与旧页面见[调整前归档](../../archive/2026-11-03-院落示例成果提取重组前/README.md)。
