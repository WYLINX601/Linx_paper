# 统一原型基础关系完整性审核与修改意见

**审核日期：2026-11-02｜状态：只读审核完成，修改建议待讨论，未实施。**

## 结论

本轮确认两类局部关系漏登：**前廊 S04 与四根廊柱 C01—C04**、**院门外部参照区 S06 与南院墙 W10 的门洞两旁局部**。另发现屋顶覆盖字段口径、空间边界局部定位与跨模块参照查询需要完善。没有证据表明需要推倒重建、复制对象或把全部缺少的直接边都补出来。

审核已覆盖当前实际数据库的 **56 个节点、285 条关系、27 种关系类型**：其中55个来自模型，另1个是来源快照元数据，不是建筑对象。主会话逐对象检查，另有独立审核过程。56项结构与选定几何检查通过、285条既有边的应用端点/角色检查通过，但这些通过不等于“基础建筑关系已经完整”。

**本轮未写 Paper 案例、未写数据库、未发布待发的2.1成果。** 审核末尾重新核对7份Paper输入的SHA及实际图指纹，均与审核起点一致。

## 2. 按建议处理顺序列出

### 审01｜优先补齐前廊—四根廊柱关系

**性质：确定漏登。优先级：P1。** 独立复核对应F01。

- **现状：** C01—C04已有主屋B01成员关系、RF01历史合成系统支承关系、S05北侧边界参与，但与S04没有任何直接关系。不能用共同归B01或通过S05可达代替S04自身的边界事实。
- **建议：** 复用四根原柱，增加`S04 → BOUNDARY_PARTICIPANT → C01—C04`，角色为南侧开放边界的局部柱截面。若将来决定完全派生而不存边，也须提供等价的明确空间边界查询；本例优先沿用既有持久化边界模式。
- **局部范围：** 在S04南界 `y=0, x=0—9.6`、`z=1m`切片上，柱截线依次是`[0,0.14]`、`[3.06,3.34]`、`[6.26,6.54]`、`[9.46,9.6]`，长度合计`0.84m`。S05分析北界从`x=0.12`开始，因此不能照搬其端柱0.02m区间。
- **边界：** 不新建柱、不把柱列当连续墙、不声称三维包含或结构受力；计算实体界定长度时，墙柱重叠必须求并集，不能把0.84m直接加墙长。
- **验收：** 从S04查询准确返回原有四柱及各自范围、分析层位、几何版本和合成来源；从柱反查同时区分S04南界和S05北界。
- **定位：** `model-staged.json /nodes/4/geometry`、`/nodes/17—20/geometry`；既有`BOUND-S05-C01—C04`位于`/relationships/195—198`；全关系端点筛选的S04—柱结果为空。

### 审02｜补齐院门外侧空间与南院墙的局部联系

**性质：确定漏登。优先级：P1。** 独立复核对应F03。

- **现状：** I05已经关联S05院内侧、S06院外侧和宿主W10，这三项不缺。但S06没有任何BOUNDARY_PARTICIPANT记录。
- **证据：** S06北边在`y=-4.92, x=3.8—5.8`，与W10南外表面对应。在`z=1m`扣去I05的`x=4—5.6`后，仍有`[3.8,4]`及`[5.6,5.8]`两段墙，各0.2m，合计0.4m。
- **建议：** 增加`S06 → BOUNDARY_PARTICIPANT → W10`，限定北侧的两个局部墙段，角色沿用wall-boundary；也可采用等价、可追溯的局部派生视图，不另造墙。
- **边界：** 不能把整条W10、整个2m边界或1.6m门洞都记成实体围合。墙轴`y=-4.8`至外边界的0.12m是已有厚度/定位口径，不是应当抹掉的几何断裂。
- **验收：** 查询得到W10的两个实体段及0.4m合计，洞口扣除可追溯；保留I05两侧和宿主身份。
- **定位：** `/nodes/6/geometry`、`/nodes/16/geometry`、`/nodes/26/geometry`，关系`R042—R044`。全关系筛选S06的BOUNDARY_PARTICIPANT为空。

### 审03｜明确屋顶—空间覆盖，纠正“前院无盖”的含义

**性质：覆盖口径与查询能力需要完善，不把缺少直接边一律判为漏建。优先级：P1。** 独立复核对应F02。

RF01的水平投影为`x=-0.6—10.2, y=-0.6—7.8`，RS01/RS02的投影并集与它一致。

| 空间 | RF01投影覆盖结果 | 本轮解释 |
|---|---|---|
| S01堂屋、S02西室、S03东室、S04前廊 | 各自声明分析矩形全部落入屋顶投影 | 可建立“由哪个屋顶覆盖、覆盖什么范围”的查询 |
| S05前院 | 北缘`[0.12,-0.6]—[9.48,0]`覆盖5.616㎡；占43.8048㎡约12.8205% | 不能无条件将`coverState=uncovered`解释为全域零覆盖 |
| S06外部参照区 | 与RF01投影交集为0 | 只说明不在该屋顶投影内，不证明没有其他未记录顶盖 |

**建议：** 分开维护“总体开敞/有盖空间类型”和“指定屋顶的局部投影覆盖”。S05仍可称开敞院落，但不把它解释成完全没有出檐覆盖。优先建立有输入版本、范围及面积口径的派生查询；如需在实体网络长期展示覆盖提供者，再定义限定覆盖边，不为此强建屋顶Interface或每个覆盖区节点。

**验收：** 六个空间覆盖可复算，前廊全覆盖和前院出檐均不遗漏；修改屋顶几何时查询重新计算或明确失效。原有D03面积按声明空间矩形统计，并非无盖净面积；本轮不把该既有面积结果笼统判错，也不擅自改变S05边界来迁就标签。

**不能推出：** 三维空间包含、实际防雨、下方净高、结构支承。屋顶覆盖与侧向实体围合分别计算。

**定位：** `/nodes/21/geometry`、`/nodes/40—41/geometry`、`/nodes/1—6/geometry`、`/nodes/5/properties/coverState`。

### 审04｜让开放界面的局部柱占用可查询，但不强加障碍边

**性质：派生查询与净空验证边界。优先级：P2。** 独立复核对应F05。

- **现状：** I04的两侧空间已齐；9.32m只是端点跨度。C02/C03在其中，C01/C04仅限定端点。已有关系和几何足以通过`I04 → S05 → 柱`再裁取I04局部范围来识别占用，因此不把“I04未直接连每根柱”定为必补错误。
- **建议：** 增加局部查询/展示，返回参与柱ID、局部区间及范围版本，避免只在说明文字中写“中间有柱”。不机械复制4条I04→柱边，不把柱标为opening-host。
- **复算：** 只扣已知柱截面可得到`[0.14,3.06]`、`[3.34,6.26]`、`[6.54,9.46]`三个各2.92m的平面开敞段；这不是三条经过验证的步行通道，不能将其总和称连续净宽。
- **通行状态：** 现有5条DIRECT_ACCESS_TO均明确`geometryClearanceValidated=false`，正确保留为旧合成情境断言，不需要因为本审核直接删除。I05的1.6m仍是分析高度范围，不当成人步行净空验证。
- **验收：** “已知平面开敞段”“旧情境可达”“净空已验证”明确区分；实际通行未验证时不返回已验证结论。
- **定位：** `/nodes/25/geometry`及其`widthBasis/clearWidthState`，`/nodes/26/properties/heightMeaning`；通行边`R030/R034/R038/R041/R045`。

### 审05｜补局部边界口径，重点核对墙端和转角

**性质：已有边粒度不足及条件性候选，不是立即批量补边。优先级：P2。** 主会话补充；独立审核亦指出S04墙端取决于分析边界口径。

- S01—S04的15条墙边界参与关系`R059—R073`仍是`rangeState=not-localized`。这不等于这些边错误，但不能拿来回答“哪一段”“多长”或声称边界已完整定位。
- 对声明矩形与有限墙厚包络做毛截面初筛，另出现S04与W04/W05墙端、W08/W09转角局部候选。它们与相邻墙/柱可能重叠；S04又采用轴线分析矩形而非统一净边界，不能照见交集就直接造边。
- **建议：** 先明确每个空间使用轴线、内侧净边界还是分析裁切线，再按任务给原有边补局部编号、范围与来源；对上述候选确定是独立边界参与、并集覆盖还是不纳入。边段继续作为属性，不自动节点化。
- **验收：** 对每段能区分实体、开放、部分定位和未知；不要求人为封闭开敞空间，不把同一部位重复计入实体长度。没有定位的边继续明确标注，不能混入已定位量化结果。
- **定位：** `/relationships/58—72`；`/nodes/4/geometry`及`/nodes/10—11/geometry`、`/nodes/14—15/geometry`。本轮毛几何初筛未扣所有洞口，不能作为最终净边界结果。

### 审06｜接续外部空间与街段参照，不强造包含或通行

**性质：跨模块查询/角色选择。优先级：P2。** 独立复核对应F04。

- **边界：** ST01保持SpatialReference，S06保持Space；不合并身份、不使用ST01→BOT_HAS_SPACE、不自动增加通行边。TP01第0号样点与ST01中心线端点吻合也可查询，不为让图连通而强制存边。
- **验收：** 能重算2.76㎡交集和同层关系，同时说明这不等于可通行、净宽合格或无障碍；S06仍不计入宅院U01的局部面积窗。
- **定位：** `/nodes/6/geometry`、`/nodes/53/geometry`、`/nodes/54/geometry/pointsXYZ/0`；既有`D05-LEFT/D05-RIGHT/D05-GROUND`保留。

### 审07｜把逐对象基础关系检查纳入以后验收

**性质：流程修订建议。优先级：P1。** 不增加研究对象，不恢复暂停范围。

今后不能只验证“现有JSON能入库、已有查询能返回”。验收还应核对：

1. 每个构件的组织归属，以及它实际参与哪些已声明空间的边界；二者分别查。
2. 每个界面的已知两侧、宿主或开放性质；允许有证据的未知，不强迫统一边数。
3. 局部墙柱范围、开口扣除、转角重叠、顶盖投影与空间总体类型是否一致。
4. 新模块是否复用原对象，并能解释与既有空间/参照的衔接；已有派生查询足够时不强存冗余边。
5. 缺关系时区分确定遗漏、待几何核对、可选派生、不适用、证据未知和研究范围暂停。

**验收反例：** 删去一条S04柱参与应能报警；把前院零覆盖与出檐并存应报警；I08—I10缺外侧不误报；I01/I04无墙宿主不误报；B03不归U01、来源快照无建筑边均不误报。

这些是建议的后续语义验收要求，**尚未写成正式主源校验器或部署到数据库**。本轮审核脚本只在临时目录运行，不能称已实现持续监控。
