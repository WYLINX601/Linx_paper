# 学术助手恢复与回退

先结束学术档案正在运行的任务，再进行下列操作。停止学术档案不会卸载其他档案。以下是恢复方法，本次未执行回退。

## 暂停使用

在 Linux 执行：

```sh
/home/linx/.local/bin/hermes -p academic gateway stop
systemctl --user disable --now hermes-academic-obsidian-tunnel.service
```

当前 Hermes 的命名档案 `gateway stop` 会建立 `gateway.parked` 标记并从现有多档案网关停用 academic；数据、技能、会话和凭证文件保留。**不要使用 `profile delete` 作为可恢复停用方式**，该命令会实际删除档案目录。

恢复使用：

```sh
systemctl --user enable --now hermes-academic-obsidian-tunnel.service
/home/linx/.local/bin/hermes -p academic gateway start
/home/linx/.hermes/profiles/academic/bin/mac-paper status
```

本次新增目录：`.obsidian/plugins/obsidian-local-rest-api/`。在 Obsidian 停用 Local REST API with MCP 后，把该目录移到库外保留；将启用列表与上述备份比较，只撤回本次新增项。如果此后又安装了其他插件，不要整份覆盖当前列表。重新加载插件或重启 Obsidian，保留原 Simple Mind Map。

插件 `data.json` 含 API 密钥和本地证书，只能保存在受限位置。Linux `.env` 是 academic 专用，停用后可以与该档案一起受限归档。不要把这些文件复制到项目笔记或公开仓库。

## Zotero 与 Linux 环境

Mac 的 `~/.local/share/hermes-academic/zotero_compat.py` 是本次新增的兼容入口，原 Zotero MCP 安装包未改。停用 academic 后可将该目录受限归档；Codex 原有 Zotero 接入仍使用原入口。

学术配置在切换兼容入口前保存于 Linux `academic/backups/config-before-zotero-compat.yaml`。仅想撤回兼容层时，比较并只恢复 `mcp_servers.zotero.args`，保留之后的工具范围及其他设置；原解析器对本次两篇 PDF 的已知失败也会随之恢复。

本次 Linux 环境都在 `academic/` 下（技能、Python、Node 包、LibreOffice、辅助命令），没有全局卸载工具或修改系统软件。初始其他档案配置备份在：

`/home/linx/.hermes/backups/academic-setup-20261026T135154Z`

不要用该目录整体覆盖其他档案；它只用于比对与有针对性的恢复。

## 恢复某个项目文件

`mac-paper` 覆盖前的文件和元数据保存在 Mac `.hermes-academic-backups/`。先看对应元数据中的原路径、摘要、时间与 restore hint，确认待恢复版本；再读取目标当前摘要，用同样的条件写入流程恢复。恢复不等于研究内容重新通过验证。
