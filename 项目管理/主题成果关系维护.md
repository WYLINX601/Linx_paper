# 主题与成果关系维护

## 分工

- 主题页维护研究问题、分析、依据和判断；成果包维护具体产物。
- 各成果包README的`artifact_*`字段是对应关系的唯一维护位置。主题中的成果表、两区总目录及成果入口中的关系说明均由这些字段生成，不各自手工维护一套。
- `artifact_primary_topic`是主要维护归口，不是原创性归属或科学重要性排序。`artifact_topic_roles`注明每个主题中的具体用途。
- `artifact_group`标注维护层级：现行主源、现行候选、过程原型、统一原型入口、展示与讨论、文献核查记录。它描述维护状态，不表示研究质量或完成度；成果目录与主题表由该字段派生。
- `artifact_relations`（可选）只记录有明确依据的成果递进关系，写在“后继”包上，方向为后继→前置；第一版类型为`merges`（合并）、`supersedes`（替代）、`builds_on`（建立于）。目标限成果包README；无证据留空，不由版本号推断。
- `artifact_state`是依据已有说明作出的导航概述。精确审核状态、版本、参数与证据仍以`artifact_main_sources`指向的主源为准；如有冲突先核对，不提升为已验证。
- `artifact_boundary`明确候选、合成、历史、展示等限制。跨主题复用不复制数据，也不自动形成章节采用关系。

## 更新流程

1. 阅读最新成果README和具体主源；用最新SHA经mac-paper保护写回关系字段。
2. 用本机Python运行`项目管理/健康检查/topic_artifact_views.py --output-dir <Paper库外工作目录>`生成候选视图。脚本只读主源，不直接覆盖库。
3. 审核差异；用当前目标SHA通过mac-paper上传候选文件。发生冲突重新读取并生成，不覆盖别人新写的内容。
4. 运行同一脚本的`--check`，确认所有派生关系视图一致；再检查新链接和状态边界。不要通过刷新研究依赖基线消除语义待复核提示。

生成器依赖当前Mac学术环境已有的PyYAML；它读取实际成果一级目录，因此新增包必须配齐README字段。源文件不存在、主题无对应页或派生视图过期都会使检查失败。

## 本轮范围

只补关系字段、入口与派生表；不移动或删除已有成果，不修改模型数据、原生导图载荷、历史证据，不宣称重新完成文献精读、数据库查询或实证验收。

本轮核验与保留问题见[[项目管理/主题成果关系核验.md]]。

## 与动态大纲衔接

主题角色加入后，统一使用[[项目管理/动态研究体系.md|动态研究体系]]中的`research_structure.py`生成全部关系视图。原`topic_artifact_views.py`仍可检查成果关系子集，但不负责大纲、路径及角色卡。角色、章节采用、成果用途各在所属主源维护，不相互复制。

## 当前命名与维护入口

主题的主要角色落实到实际目录和主文档名称：`〔主角色〕主题名`；`topic_title`与`wiki_id`区分逻辑名和稳定身份。成果目录使用`〔产物类型〕成果名`，类型来自README的`artifact_label`，名称来自`artifact_title`。主要角色或类型调整需显式改名及全引用检查，不能只改属性。

大纲每节的问题、证据要求和完成判据在YAML维护；导航及图为派生视图，不另写第二份。操作与恢复见[[项目管理/动态研究体系.md]]和[[项目管理/学术大纲与角色命名修订说明.md]]。
