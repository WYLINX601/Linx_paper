# 传统民居资料收集清单设计（共用口径）

这份清单把[夏雷论文数据收集明细](../../文献库/夏雷-2020-东北严寒地区村落风貌数据库-数据收集工作明细.md)中的准备、信息拆解、来源记录和调查组织经验，转化为本研究的候选收集项。现有资料依据见[目录盘点](目录梳理与资料基础盘点.md)，研究用途依据[当前项目context](../../context/PROJECT_CONTEXT.md)。

**版本性质：目录盘点后的第一版工作设计。** 项目已确认聚焦传统民居，但本表的字段、优先级、试采组合和完成要求均为建议，尚未经试采验证；不构成正式样本名单或定稿数据字典。收集项目不要求每栋、每村全部齐备，具体范围按研究用途和可获取条件调整。

实际管理入口为[资料收集总表](资料收集总表.md)。各村已有依据、来源线索与后续进度分别维护在[敕木山管理表](敕木山/资料收集管理表.md)、[大张坑管理表](大张坑/资料收集管理表.md)；本文件保留共用项目定义、优先级、获取要求和夏雷借鉴依据，不再维护并排的两村状态。

## 一、怎么使用

- **P0：先解决的条件。** 对象、范围、来源、时点和数据入口；这些不清楚，后面的特征容易归错。
- **P1：拟纳入试采的核心内容。** 用于民居形态、组合关系及证据记录；空间不可进入或不可见时如实记缺。
- **P2：按问题或典型案例深化。** 文化解释、细部构造及高成本测量，明确用途后再采。
- **已有资料状态**使用“已有来源／历史描述／图像线索／类型参考／待取原件／待核入口”等文字，不使用“完成率”。现有资料通常只覆盖某一来源或实例。
- 共用项目使用A01等编号；分村表加CMS或DZK前缀，原有CMS-M／DZK-M资料编号继续用于证据追溯。
- **借鉴依据**中的夏雷P、R、H等编号指向其明细表，不代表景宁已采到相同数据。“本研究补充”表示由当前目标、两村缺口或本次组织建议提出，不声称来自夏雷原文。
- “后续来源／做法”全部是拟获取路径。具名线索已存在；拟询问的机构、作者、团队或住户是否持有材料仍待确认。

建议每次推进一项时，保留“对象／片区、任务状态、获得的资料ID、剩余缺口、核对日期”。资料到手与资料可用分别判断：一张可打开的图片，可能仍然没有可确认的建筑身份。

## 十三、记录方式设计：三张表各管一件事

目前继续使用两村现有资料索引。以下是**新增记录的结构建议**，尚未批量生成建筑记录、特征值或图谱实例。

### 1. 资料台账：这份材料是什么、从哪里来

沿用CMS-M与DZK-M编号，新增材料按各村既有编号顺延。材料类型区分论文／档案／网页／照片／图纸／模型／访谈／测量记录；同源裁切挂回母材料。

| 字段组 | 建议记录内容 | 填写要点 |
| --- | --- | --- |
| 身份与位置 | 资料ID、题名、原件路径、工作副本路径、母资料ID | 不用资料ID代替建筑ID；保留已有编号 |
| 来源与定位 | 作者／机构、出版信息、URL、页码／图号／音频时间段 | 选择与材料相符的定位方式，不要求所有字段都有 |
| 时间与覆盖 | 调查／拍摄／发布／取得日期，村落、片区及对象范围 | 不详单列；集体描述不下放到单体 |
| 状态与条件 | 已取得／仅线索、是否已读、清晰度／尺度／基准、可用范围 | “文件存在”和“可用于某分析”分别记 |
| 来源关系 | 转引、裁切、渲染、模型导出与版本、署名／使用条件 | 不把派生副本当新增独立来源 |

### 2. 观察／提取记录：从材料中得到了什么

| 字段组 | 建议记录内容 | 填写要点 |
| --- | --- | --- |
| 对象 | 已核对象号或“待对应称谓”、村落／组团／住宅／部位 | 身份未定可以记录，不提前制造确定实体 |
| 内容 | 收集项编号、原词、原始描述／原值、单位、候选标准词 | 原词与整理词并存；一条记录尽量表达一项可查事实 |
| 证据 | 资料ID及具体定位、观察／调查时点、记录方式 | 区分原文陈述、图像观察、实测、口述、计算和解释 |
| 空间 | 照片部位、图上位置或模型版本／区域入口 | 三维未对应时留为“未建立”，不填示例区域 |
| 判读与复核 | 身份对应程度、可见范围、冲突／缺失原因、复核状态 | “尚未看到”不等于“没有”；结论可追溯到依据 |

现有资料的试填示例已分别放入两村管理表末尾，随本村证据一同查看。

### 3. 收集任务：还需要做什么、做到哪一步

| 必要字段 | 建议填法 |
| --- | --- |
| 任务号、对象／片区、收集项编号 | 关联T号与A—I项；同一项可在不同住宅产生不同任务 |
