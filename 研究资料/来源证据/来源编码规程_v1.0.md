# 来源编码接续规程（V1.0）

**结论：** 既有文献、证据与去重候选主键不重编、不覆盖；政策导则与法定名录使用 `POL_` 前缀，样本村保护规划使用 `PLN_` 前缀，按村增量登记。本规程是**编码与登记规则**，不表示 `POL_01`、`PLN_DN_01` 等文件已经取得或核验；截至 2026-11-23 只做前缀预留，未新建实际条目。

## 1. 既有主键保持稳定

| 前缀 | 现行含义 | 维护位置 | 本规程处理 |
|---|---|---|---|
| `L01`—`L23` | Zotero 已建卡的 23 篇畲族文献 | [文献库](../../文献库/README.md)、单篇阅读卡片 | 继续沿用，不因新增来源重排或改号 |
| `E001`—`E305` | 已提取的 305 条证据记录 | [研究资料/来源证据](README.md)、证据表与 JSON | 继续沿用；新增证据从 `E306` 起增量编号 |
| `D001`—`D012` | 跨文献同一遗存去重候选组 | [跨文献遗存实体去重候选表](2026-10-06-跨文献遗存实体去重候选表.md) | 继续沿用；候选组不是建筑唯一编号 |
| 敕木山 29 条记录 | 首批村落资料包内的资料记录 | [敕木山分村入口](../村落资料/敕木山/README.md) | 原位复用，不并入 `L/E/D` 重编号 |
| 大张坑 40 条资料单元 | 首批村落资料包内的资料单元 | [大张坑分村入口](../村落资料/大张坑/README.md) | 原位复用；不与敕木山横比或合计为建筑数 |

**规则：** 同一对象已有 `L/E/D` 编号时优先引用原条目；新增材料只在必要时建立新条目，并在条目内写 `relatedIds`，不复制成第二份主记录。

## 2. 新增 `POL_`：政策导则与法定名录

**适用范围：** 省级／县级政策文件、保护利用指南、法定保护名录、传统村落与特色村寨批次通知及其附件。

**编号与首批预留：**

| 编号 | 预留对象 | 状态 |
|---|---|---|
| `POL_01` | 《浙江省传统村落保护利用指南》（2025） | 预留；文件与版本待核 |
| `POL_02` | 《景宁畲族自治县传统建筑保护名录》（景政通〔2021〕6 号） | 预留；文号与附件待核 |
| `POL_03` | 省保及传统村落／特色村寨批次通知附件 | 预留；具体批次待核 |
| `POL_04`—`POL_xx` | 后续政策、名录与通知 | 按取得顺序增量编号 |

**登记字段（最低）：**

- `id`：`POL_01` 等稳定编号
- `title`：文件全称
- `issuer`：发布机关
- `documentNo`：文号（无文号写“无”并说明）
- `versionDate`：发布／修订日期
- `sourceType`：政策／指南／名录／通知附件
- `filePath`：原件或工作副本路径
- `sha256`：文件哈希
- `pageOffset`：PDF 物理页与印刷页差值（无印刷页码写“不适用”并说明）
- `accessedAt`：取得日期
- `verificationStatus`：已取得／待取得／仅有题录／待核

## 3. 新增 `PLN_`：样本村法定保护规划

**适用范围：** 样本村的《传统村落保护发展规划》文本、建筑分类保护图则、保护范围图与相关附件。

**编号规则：** `PLN_<村码>_<两位序号>`。村码使用稳定短码，首次出现时在登记表中登记全称与行政归属；不得用村名首字临时推断其他村码。

**首批示例（仅为格式示例，不代表文件已取得）：**

| 编号 | 对应村 | 状态 |
|---|---|---|
| `PLN_DN_01` | 东弄村规划文本 | 格式示例；文件待核 |
| `PLN_ZH_01` | 周湖村规划文本 | 格式示例；文件待核 |

**登记字段（最低）：**

- `id`：`PLN_DN_01` 等
- `village`：村名全称
- `currentAdmin`：现行行政村（2019 年调整后）
- `historicalVillage`：历史自然村／旧称（有则填）
- `planTitle`：规划全称
- `planPeriod`：规划期限
- `compiler`：编制单位
- `approval`：批复机关与文号（有则填）
- `filePath`：原件或工作副本路径
- `sha256`：文件哈希
- `pageOffset`：PDF 物理页与印刷页差值
- `figureLocator`：图则编号／图名／页码
- `accessedAt`：取得日期
- `verificationStatus`：已取得／待取得／仅有题录／待核

## 4. 证据状态与字段挂接

新增来源进入图谱时，按 U18 使用两套字段：

- `evidenceStatus`：`规划记载`、`实测观察`、`账实冲突`、`档案缺口`
- `epistemicState`：`已知存在`、`明确无`、`未知_文献未载`、`未知_航测遮挡`、`不适用`
- 未知时必填 `unknownReason`；账实冲突时保留 `plannedValue`／`observedValue` 及各自 `locator`。

**来源与证据的分层：**

1. `POL_`／`PLN_` 是**来源**，不是证据本身；引用时必须落到具体条款、图则或页码。
2. `E` 编号是**证据记录**，可引用 `POL_`／`PLN_`／`L` 作为来源。
3. 图谱边或节点属性引用 `sourceUid` 时，指向来源条目，不指向摘要或二手概述。
4. 同一规划文本的不同版本分别登记，不覆盖旧版本；版本差异写入 `versionNote`。

## 5. 与第 4.1／4.3 节的接口

- **4.1 实证样本与多源数据准备：** 用 `PLN_` 登记各村规划底本、图则与 `pageOffset`；用 `POL_` 登记名录与导则；在样本表中引用来源编号，不复制全文。
- **4.3 知识融合与证据状态标注：** 用 `POL_`／`PLN_` 的条款定位支撑 `ProtectionClause` 与 `REGULATED_BY_CLAUSE`；用 `L`／`E` 支撑建筑形态与文献事实；用 `D` 组处理跨文献同一遗存候选。
- **并村异名：** 以 `controlled_vocab_v1.2.yaml` 的 `village_mergers_and_aliases` 为候选词表；具体村名、行政村归属与规划图则不一致时，回到原始附件核对，不以词表自动裁定。

## 6. 当前状态与待办

- 本规程只完成编码规则与字段设计；**没有新建 `POL_` 或 `PLN_` 实际条目**。
- `POL_01`—`POL_03` 与 `PLN_DN_01`、`PLN_ZH_01` 均为预留／格式示例，文件是否取得、版本与页码待核。
- 后续登记时，先在[来源证据索引](README.md)增加入口，再建立条目；不覆盖既有 `L/E/D` 条目。
- 本规程不改变文献库、村落资料包、双基准、案例 JSON 或 Neo4j 的现有状态。
