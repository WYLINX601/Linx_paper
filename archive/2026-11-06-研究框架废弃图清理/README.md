# 研究框架废弃图与过程工件清理

根据用户“废弃的图要做好清理”的要求，归档本轮自动绘图目录中已被接续的候选、重复总览、逐章校对图、构造模板与历史执行记录，共65个文件。不是重画或新增研究成果；本次不修改正式画布、正文、章目、模型、案例或数据库。

- [绘图过程原件ZIP](绘图过程原件.zip)：按清理前Paper完整相对路径保存；另有4份清理前说明与回执快照。原生可编辑候选及构造JSON均按原字节保留。
- [逐文件路径与SHA-256](manifest.json)：原路径同时是ZIP内成员路径。核验归档上传后的完整ZIP及每个成员后，才清理工作副本。
- [清理验收](清理验收.json)：实际移出清单、当前文件树与保留文件哈希的最终回读记录；归档不是恢复演练。
- [[Excalidraw/Drawing 2026-11-05 19.54.23.excalidraw.md|唯一现行详细框架画布]]及同名PNG继续在原位置；当前SVG、第三章阅读局部、布局工作表示与最近一次图稿验收仍在[[项目管理/绘图自动化/论文研究框架Excalidraw/README.md|维护入口]]。
- [[研究成果/〔研究路线〕论文研究路径/README.md|研究路径与框架入口]]中的draw.io概览版及配套导出仍保留。概览SVG目前被1106汇报画布引用，不能仅因它早于详细图就误判为废弃；其他研究图、目录导图及原始来源不在本次清理范围。

## 恢复与历史路径

ZIP中的Markdown、原生场景、JSON回执及请求保留执行时的路径和内容；其中候选路径、导出路径和旧viewId是历史记录，不表示仍有一份现行图。不要为消除旧路径而改写过去的执行结果，不要直接重放旧请求。

恢复时从ZIP按manifest选择原成员，比较当前目标与未保存编辑；新建用mac-paper的expect-missing，覆盖用最新SHA保护写回。只恢复需要的图，不将整批候选重新铺回工作目录。清理工作副本使用Obsidian默认回收站方式，不执行永久删除。
