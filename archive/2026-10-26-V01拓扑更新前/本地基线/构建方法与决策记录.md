## R01：用最少信息补齐墙与墙的交接

### 1. 问题、目标与范围

**提出来源：**2026-10-26，用户从前院图谱发现墙之间缺少连接，要求先查理论、按最简／剃刀原则设计墙关系，并为后续墙—柱及屋面关系提出推广思路；要求保留论文可回溯的构建经验。

**当前事实：**主源有10个Wall实例、9种基础关系；2026-10-26通过Neo4j MCP只读确认10面墙之间没有直接关系。空间—墙的BOUNDED_BY只能说明边界参与，不能替代墙—墙交接。图谱力导向布局中的节点位置不代表建筑坐标。

本轮先回答三类问题：某墙直接与哪些墙交接；交接发生在各自端部还是中段；由这些交接和几何可以得到什么转折、连续与围合线索。只增加这些任务必需的表达，不为字段数量或关系数量设目标。

**工作范围：**同一案例、同一局部米制坐标系、已明确共同层位的直线墙轴，在平面分析中的单点交接。当前V01统一地坪Z=0，来自合成设定；这一范围不覆盖真实墙体接触面、错层连接、曲墙、复合墙层或砌筑做法。

### 3. 从依据到本研究规则

**采用：墙轴交接 `AXIS_JOINS`。**它是本研究的关系名，不是IFC或BOT的原样术语。定义为：在声明的同一平面分析范围和共同层位内，两条直线墙轴有且仅有一个共同点。

- 端—端交接：交点同时位于两条轴线边界。结合夹角可描述共线延续或转角。
- 端—中段交接：交点是一条轴线的边界点、另一条轴线的内部点。
- 中段—中段交叉：交点同时位于两条轴线内部，仍可使用同一种边，以双方部位区分。
- 共线共享一段长度：进入重叠待审，检查重复对象、分段口径或实际重合，不自动归为普通单点交接。

这是对S01与S03的任务性组合：S01提供交接部位词汇；S03支持几何判据；如何合并为一条LPG边及如何处理例外，是本研究的设计决定。**本轮程序并未实现完整DE-9IM矩阵，而是实现该任务所需的直线段交集与交点部位判断。**

OGC的Touches可同时包含端—端与端—中段，并不能仅凭一个Touches布尔值区分二者。中段—中段单点相交对应线之间的Crosses情形。不要把前述所有情况命名为同一种严格数学意义上的Touches。

本关系**对称、不自反、不传递**：A与B交接、B与C交接，不推出A与C直接交接。Neo4j只存一条边，按稳定uid排序选存储方向；使用无向模式查询。双方属性始终相对存储source与target解释，不因查询从另一端进入就交换原属性。反向存储时必须同时交换双方部位。

### 4. 最小存储表达

沿用现有Wall节点，只增加AXIS_JOINS这一种关系；不增加端点或交接实例节点。每条边仅增加3项建筑描述字段与1项规则引用；现有编号、来源、状态字段按原模型格式复用。

| 字段 | 是否保存 | 作用与边界 |
| --- | --- | --- |
| source／target | 沿用边端点 | 连接两个已有墙实例；同一对直线轴在本轮规则下最多一条正向存储边 |
| atSource | 必需 | source墙交点为ATSTART、ATEND或ATPATH |
| atTarget | 必需 | target墙交点为ATSTART、ATEND或ATPATH |
| junctionXY | 必需 | 两个米制数值定位交点；支持回看平面及沿墙定位中段交接，不另建点节点 |
| ruleId | 必需 | WJ-01-v1，链接本记录、算法及冻结来源；坐标系和规则集中说明 |
| status／evidence | 复用既有记录字段 | 当前为synthetic_geometry_derived、EV01；图纸EV02是同源生成展示，不增加独立证据数量 |
| 夹角、L／T／X等形态名 | 仅在分析结果计算 | 可由双方部位与轴线方向得到，暂不与基础边重复维护；L/T/X包含几何形态判断，不等同于纯拓扑不变量 |
| 是否连接、双向标记 | 不重复保存 | 边的存在和关系定义已经表达；没有边不自动证明不连接 |
| 置信度、接触面积、砌筑方式、受力 | 本轮不补造 | 未实施概率校准、实体接触计算或构造核查；需要时按独立证据扩展 |

具体候选记录：

```json
{
  "id": "WJ-W08-W10",
  "source": "W08",
  "target": "W10",
  "type": "AXIS_JOINS",
  "status": "synthetic_geometry_derived",
  "evidence": ["EV01"],
  "properties": {
    "atSource": "ATSTART",
    "atTarget": "ATSTART",
    "junctionXY": [0.0, -4.8],
    "ruleId": "WJ-01-v1"
  }
}
```

W08与W10的夹角90°是该记录结合主源轴线计算的结果。junctionXY是可重算的定位缓存，必须随来源变化重算；a/b端点顺序也属于来源版本。将来以稳定uid入库时，只加当前导入所需的通用标识和来源追溯属性，不再抄录一份墙体几何到每条边。

本轮选择边的理由是任务涉及两面墙，交接位置无需独立管理。**只有交接部位需要独立身份、关联多方共同事件、病害或多次观察时，再考虑独立节点。**三个对象相遇也不必机械增加节点；只有必须保留“共同的同一次交接”语义而两两边不足时才升级。

### 5. 判定规则 WJ-01-v1

1. 检查对象身份、同一案例、坐标系、分析层位、轴线非零长度和当前几何版本。真实资料缺少层位时保留候选，不从XY猜测同层；不同层位的投影交叉不按本规则建边。
2. 对两条有限直线段求交：无交点→本轮轴线分离；单点→判断双方起点／终点／内部；共享线段→重叠待审。不能只对无限延长线求交。
3. 单点交接生成一条边，并保存交点及双方部位；重叠、退化或信息不足只进入核验记录。当前只枚举10面墙的45个无序对，不为33组轴线分离添加否定边。
4. 在本轮合成数据中，使用十进制数转有理数进行精确计算，不吸附、不引入测量容差。真实测绘时另按误差确定候选搜索容差，保留原始偏差及人工／独立资料核查；阈值尚未校准，不能把本程序直接当现场数据识别器。
5. 对称性和重复关系检查后，把结果标为“合成几何派生”。来源改变则重新计算受影响关系；不能只更改墙坐标、保留旧交接缓存。

额外限制：同层轴线相交仍不足以证明实体连续。墙厚、端部处理、开口、伸缩缝、施工阶段和砌筑做法均可能改变实体或构造判断。本轮所有正例仅验证声明的平面轴线语义。

尚未入库的只读查询模板（在本轮候选边正式同步后使用）：

```cypher
MATCH (w:V01:Wall {id:'W10'})-[r:AXIS_JOINS]-(other:V01:Wall)
RETURN w.name AS wall, other.name AS otherWall,
       startNode(r).id AS storedSource, r.atSource AS atStoredSource,
       endNode(r).id AS storedTarget, r.atTarget AS atStoredTarget,
       r.junctionXY AS joint, r.ruleId AS rule;
```

该查询显式给出存储方向，使无向匹配后的部位不会错配。它是拟用模板，本轮未将其保存到Browser或宣称执行已返回这些新边。

**围合分析还有一个容易误判的问题：**三个墙对象在同一个点两两交接，会在“墙为节点”的图中构成三角环，但不围出面积。判断平面围合要回到轴线交点，必要时仅在计算过程中分割几何线段并检查闭环和面积；不能把对象关系图的环数当院落数量。墙轴围成几何闭环，也不证明实体连续封闭或无法通行，仍需结合门洞和开放界面。

> 本研究以墙体交接的识别与查询需求为约束，借鉴IFC路径构件连接位置分类及OGC简单要素的平面拓扑关系定义，提出适用于同一分析层位直线墙轴的交接表达。该表达保留既有墙体实例，通过单一关系记录双方交接部位与交点位置，并以规则引用连接来源版本和判定过程。几何夹角与交接形态作为可复算的分析结果，暂不增加端点或交接实例节点。在一个合成民居案例的10面墙、45组组合上，规则生成12组单点交接；结果仅检验该表达及其实现的一致性，实体接触、构造连接及真实资料容差仍需另行验证。

## R02：墙—柱推广方案（未实施）

**分析目标：**柱是否嵌入墙端、靠近墙端或与墙分离；墙—柱如何共同组织立面与构架。先核实几何接触，再据独立资料讨论连接与支承。

**最小路线：**复用“已有对象＋直接关系＋交接部位＋依据”的形式，但将判据换为墙体平面轮廓与柱截面，结合共同高度范围。不能将墙轴与柱中心重合直接记为两个实体接触。

V01的C01位于(0,0)，柱半径0.14m，而W01／W08墙轴也到达该位置，墙厚0.24m。按当前简单轮廓展开会出现占地重叠。这既可能表示嵌入，也可能只是粗粒度几何未做端部裁切，**现阶段应记录为几何重叠待解释，不自动写成“相接”或“承重连接”**。

后续先选这一处作为对照，确认墙是否在柱边停止、绕柱还是嵌柱；然后决定是否只需一条实体接触边及部位属性。支承继续沿用已有建造关系，不从接触直接派生。判定标准和容差查证完成后再固定新关系名。

## R03：屋面—屋面推广方案（未实施）

**分析目标：**屋面如何组成屋顶，哪些边形成屋脊／斜脊／天沟，坡向和交角如何共同构成外形。

V01当前只有RF01屋顶系统节点，两片坡面由参数生成，尚无独立坡面实例。若要研究坡面之间的关系，先给确实需要的两片坡面独立身份，仍归属RF01。不能把“屋顶系统”和“坡面”当成同一粒度，也不能对RF01自己建立两坡面间的边。

**最小路线：**坡面—〔共享边界〕—坡面，先以三维边界曲线判定相交／共边，再依据高程、坡向和交线两侧形态判断脊或沟。平面投影相交不能证明三维共边；共边本身也不能区分屋脊和天沟。类型可先放在关系属性，只有屋脊需要被独立标注、测量、关联装饰或病害时再建立节点。
