一、阻断项

1. G07／classify()／CORE：输入状态判据不完整，两条分类路径并不等价。

具体问题：

  • classify() 不检查 boundaryIds；CORE 检查，但没有要求 boundaryIds、boundaryKinds、boundaryStates 三者等长。例如 IDs 为四项、kinds／states 均为三项，不能保证返回 invalid-input。
  • classify() 与 CORE 都把任意非 known 状态直接归为 unknown，没有先验证状态枚举。拼写错误与真正未知被混为一类。
  • kind='unknown'、state='known' 的矛盾组合不会被这两处判为 invalid-input；反向矛盾也只是 unknown。compile_model() 的 assert 对当前 JSON 作了较强检查，但没有同步到被称为共同表达的查询判据。
  • CORE 对缺失／null 字段没有全面显式拒绝。Cypher 的 null 逻辑不能等同于 Python 的布尔检查，不能承诺所有坏输入均稳定进入 invalid-input。

当前 A—D 的显式记录没有上述矛盾，尤其 C-W 与 D-W 区分正确；问题在“校验器保证什么”，不是四例必须重做。

最低修正：明确必填、类型、数组等长、状态枚举及 kind/state 配对约束，并让 Python 和 Cypher 使用一致的状态优先级。无需新增节点。

2. IMPORT：命名空间和允许关系类型主要由同一载荷自证，不是独立保护边界。
